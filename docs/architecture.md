# Architecture

A diagram overview (layers, module imports, the install flows, entry points, tests and CI) is in [code-map.md](code-map.md).

One shared core, thin interfaces. The graphical app (`gui.py`, tkinter) is the default and is started by `app.py`. The command line (`cli.py`) is opt-in through `gitfurl cli`. Both use the same core and safety checks. A TUI may follow.

- `doctor.py`: read-only probes with a timeout.
- `prefixes.py`: name validation and per-user location; `create_prefix()` runs `wineboot`. `wineboot_env()` gives `QUIET_WINEBOOT_ENV` (`WINEDLLOVERRIDES=mscoree,mshtml=`, no Mono or Gecko dialogs) to every Wine-runtime prefix gitfurl creates, unless the user asks for Wine's dialogs (`--wine-addons`, or the window's switch); the native route always uses it and its plan says the option or switch does not apply. `wineboot_line()` is the plan's line for it. `run_in_group(should_stop=)` lets a Stop end wineboot's group (both routes in the window).
- `runner.py`: builds an execution plan (argument list, prefix, working dir, child-only environment). `execute` runs it only after approval and writes output to a local log (mode 0600), never the environment.
- `cli.py`: argparse front end. Real actions need an explicit prefix and approval (a typed yes, or --yes). Without a terminal and without --yes they exit with status 2 and change nothing.

A dry run never falls through to real execution.

- `app.py`: entry point. No arguments opens the GUI; `cli ...` runs the CLI; anything else exits with status 2. `__main__.py` makes `python -m gitfurl` call it.
- `gui.py`: window and confirmation dialogs. Logic that can be tested without a display (`describe_plan`, `window_route`, `native_plan_for`, `native_plan_text`, `native_end_text`, `plan_checklist`) is kept in plain functions. The native route runs through `route.perform_native` on a worker thread.
- `cleanup.py`: optional removal of the installer after a good run, with the guards in the user guide.
- `prefix_delete.py`: deleting a prefix gitfurl made (`gitfurl cli prefix delete`, the library's "Delete..."). `plan_delete_prefix()` reads names and metadata only: it refuses a bad name, a path that is not exactly `prefixes_root()/NAME` or has a link in it, a non-folder, a folder with neither `drive_c` nor `system.reg`, a running Wine server (`procgroup.prefix_server_running()`) and a prefix in use (`in_use()`: own processes with its `WINEPREFIX`, a working folder or an open file inside it; the window passes its own run as `busy`); it counts the tree with `lstat` (capped) and lists the menu entries `gitfurl-NAME-*.desktop` that are regular files with `desktop.MARKER` and an `Exec` starting with `env WINEPREFIX=<path> ` (as `setup_entries.shortcut_text()` writes it), and every look-alike kept with its reason. `perform_delete_prefix()` makes every check again, opens the path part by part with `O_NOFOLLOW`, compares device and inode, and empties the tree through folder descriptors (`unlink`/`rmdir` with `dir_fd`, every folder opened `O_NOFOLLOW` and compared with its `lstat`, nothing on another device entered), stopping at the first surprise; then it removes the listed menu entries if unchanged, and writes a `.delete.log` and a timeline (`timeline.Timeline.save()`) in the log folder (0600). Starts no process.
- `changes.py`: optional before and after snapshots of the prefix and a few host places.
- `detect.py`: read-only format detection from file headers (bounded reads, no process started, nothing written). For Inno Setup it calls `inno.read_fd()` on the same open file and falls back to the ID string when the setup data cannot be read. It produces a guess; `describe()` prints the route a caller chose (`route.RouteChoice`), or "not chosen here".
- `route.py`: `choose_route()` picks native, Wine/Proton or unsupported, with the reasons, and writes nothing (it reads the archives' indexes through `extract.plan_extract`). `NativeInstallPlan.describe()` is the native plan with every step and the skipped list; `run_native()` performs the unpack after the approval (log 0600, optional event log, progress lines on the calling thread, listings of program candidates and redistributable installers, nothing run). `native_prefix_create()` creates the prefix with `wineboot` (with `WINEDLLOVERRIDES=mscoree,mshtml=` for that command only), under the memory limit's scope when it is on; `prefixes.create_prefix()` writes a `gitfurl-incomplete` marker first and removes it when wineboot exits with status 0. `unpack_memory_problem()` compares the plan's decoder memory with `MemAvailable` before the approval. `native_stops()` lists everything that stops a native run before it starts (no prefix, no Wine to create it, the memory limit unusable for wineboot, too little space or an incomplete prefix, too little memory); the command line and the window use it. `perform_native()` runs one approved native plan on a worker thread in the command line's order (scan, prefix creation, unpack) and returns a `NativeOutcome`; `NativeControl` is its Stop, which the scan, wineboot (`prefixes.run_in_group(should_stop=...)`, which ends wineboot's process group and asks this prefix's wineserver to exit) and the unpack all check. `run_native(on_progress=...)` gives the progress samples as numbers. The native route starts no process except `wineboot` (prefix creation) and `clamscan` (`--scan`).
- `farc.py`: reads a FreeArc archive's own index (footer and directory blocks) with bounded reads and CRC-32 checks, classifies each block's method (`parse_method()`: a chain of supported stages, kept by gitfurl's own names, or "a method gitfurl does not handle"; the archive's text is not kept), and summarises it for the plan. It never decodes data blocks, extracts or writes anything; anything it cannot read is refused with `FarcError`, which `detect.py` turns into a plain reason.
- `extract.py`: native extraction for `gitfurl cli extract` and the native route of `gitfurl cli install`. `plan_extract()` reads every FreeArc archive beside the installer through `farc.py` and checks every name, writing nothing; `extract()` re-reads each index, creates a new destination folder in the prefix and writes the files with `O_EXCL|O_NOFOLLOW` relative to that folder's file descriptor (names are checked through a table keyed by parent folder and case-folded name, so planning is linear in the names' length; at most 64 folder descriptors are held open), decoding each block through `farc_codecs.py`, checking CRC-32 and stopping on a cancel flag or Ctrl-C.
- `inno.py`: read-only reader for Inno Setup installers, written from a clean-room format specification. `read_setup()` finds the loader's offset table (a PE resource), or, when setup.exe has none, `<stem>-0.bin` beside it (UseSetupLdr=no, recognised by its 64-byte ID), checks the 64-byte format ID against the formats it knows, reads both header blocks (CRC-32 per 4 KiB chunk, LZMA1 or stored, output capped at 128 MiB and 64 MiB) and parses the setup header, every entry list and the file locations (at most 300,000 entries in all); a block must end exactly where its records end. For the 5.5.0 ID it tries the stock layout and the one-extra-byte layout of some modified builds and accepts only the one that fits. `read_code()` walks the compiled `[Code]` container without running it and lists string constants and DLL imports (overlapping code ranges are joined and scanned once, with a budget of 1,000,000 possible strings). `summarise()` gives the plan lines (`detect.py` shows them), `beside_files()` the archive-name preflight. `plan_inno_extract()` and `extract_inno_files()` write the stored `{app}` files for `gitfurl cli extract-inno` with the same folder handling as `extract.py` (its `_Tree`, `_make_dest` and name checks), streaming each chunk (zlib, bzip2, LZMA, LZMA2 or stored) and undoing the x86 call filter per 64 KiB, and check SHA-1/SHA-256. With disk spanning or without a loader the file data is read from slice files beside the installer (`slice_name()`, `check_slice_header()`; `_Slices` and `_SliceInput` open each with O_NOFOLLOW, check its header and size, and read a chunk on from one slice into the next); the plan checks every slice it needs and every chunk's fit before anything is written. Anything it cannot read raises `InnoError` with a plain reason; a hostile file never escapes as another exception.
- `farc_codecs.py`: streaming decoders for the methods extraction supports, `storing`, `lzma` (Python's `lzma`), `exe`, `x86` (FreeArc's `dispack070` code filter: frames of code blocks, data and raw chunks; each code block is read whole, its 19 streams made little-endian in place, and rebuilt by one table-driven loop with a 256-entry move-to-front list of call targets, then checked to have used every stream byte and given exactly its stated size), `delta`, `rep`, `4x4` (pieces each decoded by a fresh `lzma` decoder fed only that piece's payload) and `srep` (formats 1-4; earlier output, pending matches or a format 4 stream's input held in memory under one budget, or a format 4 stream read from the archive directly with `os.pread` when srep is the last stage; block checksums with `hashlib` and gitfurl's own AES-256-derived VHASH and SipHash-2-4), chained right to left as a pull pipeline that reads the block a chunk at a time. Every buffer is capped before the block is read (`stage_plan()`, `chain_memory()` for the plan's memory line); damaged data raises `CodecError` with gitfurl's own wording. Written from clean-room specifications (behaviour only). A closed-source method may also be specified by reverse engineering of its decoder, under the two-party clean room in `docs/scope.md`; nothing from that program goes into the repository.
- `portable.py`: pure functions that build the bwrap argument list and the plain-text description for the optional portable install (no process started, nothing written); `runner.py` wraps the Wine argv with it only when `InstallPlan.portable` is set.
- `scan.py`: the optional ClamAV scan (the database version from `clamscan --version`, or from `clamconf`'s folder when ClamAV 1.5 reports none): builds the `clamscan` argument list (no option that changes files), reads its output conservatively and decides (a match blocks unless overridden; an error, including a match in a scan that also had an error, always blocks); runs the `clamscan` on PATH in its own process group with a timeout. `runner.run_with_prefix` calls it before anything is created when `InstallPlan.scan` is set.
- `memlimit.py`: the memory limit: the budget from `/proc/meminfo`, availability checks (files first, then read-only `systemd-run --version` and `systemctl --user show` when a run starts), the `systemd-run --user --scope` argv that `runner.py` puts outermost, the soft-limit adjustment thread and the end-of-run report for that one unit.
- `setup_entries.py`: the opt-in setup entries on the native route (`install --apply-setup-entries`, the window's switch). `plan_setup_entries()` reads the setup's `[Registry]` and `[Icons]` entries through `inno.read_setup()`, expands constants from a small explicit table (`expand()`; anything else is skipped with the reason), places each value in `system.reg` or `user.reg` (HKCR as `HKLM\Software\Classes`; `Wow6432Node` for a 32-bit setup's `HKLM\Software` on a 64-bit prefix) and builds one `.desktop` text per program under `{app}` that the unpack writes; it writes nothing. `apply_entries()`, called by `route.run_native()` after a complete unpack, refuses while `procgroup.prefix_server_running()` finds a Wine server for the prefix, copies each registry file into the log folder (0600), edits it with `edit_registry()` (Wine's text format; only the listed values' lines and new key sections change) and renames a temporary file over it; menu entries go through `desktop._write()` and never replace a file without gitfurl's marker. It counts what it did in an `Applied` (values per registry file, menu entries, each item left out with its reason), from which `route.run_native()` adds the timeline's rows. Starts no process.
- `desktop.py`: the optional application-menu entry (`gitfurl cli desktop-entry`): writes `gitfurl.desktop` and a copy of the icon under `$XDG_DATA_HOME` after approval, creating only the folders the plan lists, each file through a new file renamed into place (mode 0644; a link in place of either file is refused). `Exec` is escaped on both levels of the Desktop Entry spec; the `python -m gitfurl` fallback adds `Path=`. Replaces or removes only files it wrote (`MARKER`; the icon when it is gitfurl's or sits beside gitfurl's entry). `apply()` records each step, so a failure is reported with what was already done. Starts no process.
- `preflight.py`: advisory checks shown before a run (measured values apart from estimates, never blocking). For a Setup run, `measure(unpacked=)` takes `route.setup_unpacked()`: `extract.unpacked_size()`, the sum of the file sizes in the indexes of the FreeArc archives beside the installer, counted only when the route's link test says they belong to it; it warns when free space is smaller.
- `namelinks.py`: the opt-in "link the archives under the names the setup expects" (`--link-names`, the window's switch). `propose()` is pure: it maps the missing names the setup expects (one numbered series) to the folder's one other numbered series of FreeArc archives with the same numbers, or gives the reason there is none. `propose_for()` reads the setup data (`inno.beside_files`, `inno.named_beside`) and the folder (`extract.find_archives`). `route.choose_route(links=)` counts the mapped archives as named. For a Setup run, `plan_staging()` plans a staging folder under `$XDG_STATE_HOME/gitfurl/staging` (links to every file and folder beside the installer, plus the expected names), `staged_plan()` starts Setup from it (`InstallPlan.source` keeps the original installer for progress), and `run_staged()` makes the folder (mode 0700) and always removes it afterwards: only links it made, with the target it gave them, then the folder if it is empty.
- `runner.py` `RunControl`: stops the run gitfurl started, through its own process group, under a lock; nothing is signalled after the run has ended.
- `progress.py`: progress from `/proc` (how far processes have read into the payload files) and the prefix size; the advisory stall detector, the "observed activity" heuristic, and Wine's crash handler (`winedbg.exe`) appearing in the prefix (none of them acts on the run). The monitor runs whenever a run has a progress callback, a stall time or a note callback, which the command line and the app always set.
- `windows.py`: advisory only. Lists the titles of the X11 windows the prefix's processes have open, with `xwininfo -root -tree` and `xprop _NET_WM_PID` (argument lists, short timeouts). Used for the stall and crash notes; never acts on a window. `window_list` caches each window's pid, and `WindowTracker` records when each window first appeared, so a stall note can name the newest, or else the one on top (`xwininfo` lists the topmost first). Windows under `MIN_SIDE` (8) pixels either way are left out as hidden helper windows, and so are windows that `xwininfo -id` reports as not viewable (asked each time, within the same time budget; a failed probe keeps the window).
- `unattended.py`: the unattended Inno Setup option: Inno Setup's documented switches (`/SP- /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /DIR= /LOG=`), the folder inside the prefix, and reading the log Setup writes there afterwards. It runs nothing itself.
- `procgroup.py`: helpers shared by everything that starts Wine in its own process group (`SigintGuard` holds Ctrl-C back on the main thread until it is safe; `group_alive`; finding the prefix's `wineserver`).
- `safety.py`: the root check shared by the app and the command line.
- `widgets.py`, `pixelfont.py`: the app's rounded widgets and block letters.
- `viewprefs.py`: the window's view settings (text size, reduce motion, remember window size) in `$XDG_CONFIG_HOME/gitfurl/view.json`, mode 0600, written only when one changes; a missing or damaged file gives the defaults, and a symbolic link is neither read nor written.
- `timeline.py`: the run's timeline: `Timeline` collects rows (time, kind, what, why) from the run's threads, folds rows that keep changing (progress, a run of data blocks with one method) into one that updates, caps the rows (2,000) and each text (300 characters, installer text through `detect.clean`), and writes each final row to `<prefix>-<stamp>.timeline.txt` beside the log (O_EXCL, O_NOFOLLOW, mode 0600). `plan_entries()` and `approval_entry()` give the plan's rows for the command line and the window; `runner.execute`/`run_with_prefix`/`run_tracked` (through `RunOptions.timeline`), `route.run_native`/`perform_native` (`timeline=`) and `extract.extract(on_event=)` add the run's rows from facts they already have. `kept()`, `latest()` and `read_text()` read saved timelines back for the window's Last run and `gitfurl cli log`. Starts no process.
- `theme.py`: colours, spacing, type sizes, the corner radius and the contrast calculation (no tkinter, so it is tested without a display).
